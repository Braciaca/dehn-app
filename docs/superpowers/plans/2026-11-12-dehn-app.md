# Dehn-App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine installierbare Web-App (PWA) für Dehn- und Mobilitätsübungen mit animiertem Katalog, eigenen Routinen und einem Player mit Timer und Pieptönen.

**Architecture:** Statische Dateien ohne Build-Schritt. Reine Logik (`sequence.js`, `timer.js`, `store.js`, Geometrie in `figure.js`) ist frei von DOM und Systemuhr und wird mit `node --test` geprüft. Ansichten sind ES-Module, die je eine Funktion `render(container, params)` exportieren.

**Tech Stack:** HTML, CSS, JavaScript (ES-Module), SVG, Web Audio API, Service Worker, `localStorage`. Tests: `node --test` (Node 24). Lokaler Server: `python -m http.server 8123`.

**Spec:** `docs/superpowers/specs/2026-11-12-dehn-app-design.md`

## Global Constraints

- Keine Abhängigkeiten, kein `package.json` nötig außer `{"type":"module"}`.
- Alle sichtbaren Texte auf Deutsch.
- Datenfelder heißen wie in der Spec: `koerperteile`, `art`, `position`, `wechselseitig`, `standardDauer`, `pause`, `eintraege`, `uebungId`, `dauer`, `seite`, `geaendert`, `lautstaerke`, `toeneAn`.
- Erlaubte Werte: `art` ∈ `statisch|dynamisch`; `position` ∈ `stehend|sitzend|boden`; `seite` ∈ `beide|links|rechts|keine`; Körperteil-Schlüssel: `nacken, schultern, brust, oberer-ruecken, unterer-ruecken, rumpf-seitlich, huefte, gesaess, oberschenkel-vorn, oberschenkel-hinten, adduktoren, waden, handgelenke`.
- Feste Zeiten: Vorbereitung 5 s, Seitenwechsel 3 s, Countdown-Töne bei 3, 2, 1 s Restzeit.
- `localStorage`-Schlüssel: `dehnapp.routinen`, `dehnapp.einstellungen`, defekte Daten nach `dehnapp.defekt`.
- Layout zuerst für 360 px Breite, ab 900 px breiteres Raster. Hell und dunkel über `prefers-color-scheme`.
- Kein Commit, solange der Nutzer nicht darum bittet (es gibt kein Repository). Die Commit-Schritte entfallen deshalb.

## Review Focus

1. Tab im Hintergrund oder Bildschirm aus während der Routine: Nach der Rückkehr zeigt der Timer die richtige Restzeit und steht im richtigen Schritt, ohne alle verpassten Töne nachzuholen. (Task 2)
2. Dauer 0, negativ, leer oder keine Zahl im Editor oder Import: Wert wird auf 5 bis 3600 s begrenzt, die App stürzt nicht ab. (Task 1, Task 3)

5. Schnelles mehrfaches Tippen auf „Weiter“/„Zurück“ am Anfang und Ende der Routine: Index bleibt im gültigen Bereich, am Ende erscheint der Abschluss genau einmal. (Task 2)

### Task 2: Timer-Zustand (`timer.js`)

**Files:**
- Create: `js/timer.js`
- Test: `tests/timer.test.js`

**Interfaces:**
- Consumes: `Step[]` aus Task 1.
- Produces: `createTimer(steps) -> Timer` mit
  - `start(now)`, `pause(now)`, `resume(now)`, `next(now)`, `prev(now)`; `now` in Millisekunden.
  - `tick(now) -> Event[]`, Events: `{type:'beep', n:3|2|1}`, `{type:'wechsel', index}`, `{type:'fertig'}`
  - `state(now) -> { index, step, remainingMs, paused, finished, elapsedTotalMs }`

Regeln: Restzeit = Schrittende − `now`. `tick` schaltet weiter, sobald die Restzeit ≤ 0 ist; überschüssige Zeit wird auf den nächsten Schritt angerechnet. Ein Beep `n` wird höchstens einmal je Schritt gemeldet, sobald Restzeit ≤ n·1000 und > (n−1)·1000. Überspringt ein `tick` mehr als 1500 ms, werden für die übersprungene Zeit keine Beeps gemeldet, nur höchstens ein `wechsel` (der letzte) und gegebenenfalls `fertig`. `prev` springt an den Anfang des aktuellen Schritts, wenn mehr als 2 s vergangen sind, sonst zum vorherigen. `next` im letzten Schritt beendet. Nach `finished` liefern alle Methoden nichts mehr; `fertig` kommt genau einmal.

- [ ] **Step 1: Tests schreiben**

```js
const steps = [{art:'vorbereitung',dauer:5,...},{art:'uebung',dauer:10,...},{art:'pause',dauer:2,...},{art:'uebung',dauer:10,...}];
test('Beeps bei 3,2,1 und Wechsel bei 0', ...)   // ticks alle 100 ms von 0 bis 5000: beep 3 @2000, 2 @3000, 1 @4000, wechsel index 1 @5000
test('Schritt kürzer als 3 s: nur passende Beeps', ...) // Pause 2 s → beep 2 beim ersten tick des Schritts, beep 1 bei 1 s Rest, beep 3 nie
test('pause friert Restzeit ein, resume setzt fort', ...) // pause@1000, state@9000 remaining 4000, resume@9000, state@10000 remaining 3000
test('tick während Pause liefert keine Events', ...)
test('großer Zeitsprung: richtiger Schritt, keine Beep-Flut', ...) // start@0, tick@16000 → index 2, Events enthalten genau ein wechsel und kein beep
test('Sprung über das Ende hinaus → fertig genau einmal', ...)
test('next/prev bleiben im Bereich', ...) // prev am Anfang → index 0; 10× next → finished, fertig einmal
test('prev nach >2 s startet Schritt neu', ...)
test('leere Schrittliste → sofort finished', ...)
```

- [ ] **Step 2:** `node --test tests/timer.test.js` → FAIL
- [ ] **Step 3:** `js/timer.js` implementieren (intern: `index`, `stepEndsAt`, `pausedRemaining`, `beeped:Set`).

### Task 4: Figur (`figure.js`)

**Files:**
- Create: `js/figure.js`
- Test: `tests/figure.test.js`

**Interfaces:**
- Produces:
  - Pose: `{ hip:[x,y], torso, head, armN:[ober,unter], armF:[ober,unter], legN:[ober,unter], legF:[ober,unter], footN, footF }`. Winkel in Grad, absolut im Bild: 0 = Segment zeigt nach oben, positiv im Uhrzeigersinn (nach rechts). Die Figur blickt in Seitenansicht nach rechts. Koordinaten im Feld 200×200, Boden bei y = 180. Fehlende Felder fallen auf `STAND` zurück. `N` = körpernah, `F` = körperfern.
  - Optional je Pose: `spine` (Zusatzwinkel des oberen Rumpfsegments relativ zum unteren, Standard 0).
  - `STAND` (aufrechte Standpose), Segmentlängen `LEN = { torsoU:28, torsoO:28, hals:8, kopfR:10, oberarm:26, unterarm:24, oberschenkel:38, unterschenkel:36, fuss:12 }`
  - `gelenke(pose, ansicht) -> { hip, mid, shoulder, head, elbowN, handN, elbowF, handF, kneeN, ankleN, toeN, kneeF, ankleF, toeF }` (jeweils `[x,y]`). In `ansicht:'front'` liegen Schultern ±14 und Hüften ±8 seitlich versetzt, `N` = rechte Bildseite.
  - `mischen(a, b, t) -> Pose` (lineare Interpolation aller Werte)
  - `spiegeln(pose) -> Pose` (tauscht N und F; in Seitenansicht wechselt so die arbeitende Seite)
  - `poseZurZeit(animation, tSek) -> Pose`: `animation = { ansicht, posen: Pose[], zyklus: number, modus: 'halten'|'pendeln', requisit?: 'stuhl'|'wand'|null }`. `pendeln`: läuft Pose 0→1→…→letzte→…→0 mit weichem Ein- und Ausblenden je Abschnitt. `halten`: geht in 1,5 s von Pose 0 zur letzten Pose und schwingt dort mit ±1,5° am `spine` im Takt `zyklus`.
  - `mountFigure(el, animation, {seite, standbild}) -> { stop() }`: zeichnet ein SVG in `el` und animiert es mit `requestAnimationFrame`. `seite:'links'` spiegelt mit `spiegeln`. Bei `standbild` oder `prefers-reduced-motion` wird nur die letzte Pose gezeichnet. Farben über CSS-Variablen `--figur`, `--figur-fern`, `--requisit`.

- [ ] **Step 1: Tests schreiben:** `gelenke(STAND,'seite')`: Kopf über Schulter über Hüfte (y aufsteigend), beide Knöchel bei y ≈ 180−Fußhöhe (±1); `mischen(a,b,0)` = a, `(a,b,1)` = b, `(a,b,0.5)` Mittelwert; `spiegeln(spiegeln(p))` = p; `poseZurZeit` im Modus `pendeln` bei t=0 und t=zyklus gleich Pose 0, bei t=zyklus/2 gleich letzter Pose; Modus `halten` bei t≥1,5 innerhalb ±1,5° der letzten Pose; Pose mit fehlenden Feldern liefert nur endliche Zahlen.
